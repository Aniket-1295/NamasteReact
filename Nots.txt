Styles.Scss

// 1️⃣ Variables
$primary-color: #3498db;
$secondary-color: #2ecc71;
$font-stack: 'Poppins', sans-serif;

// 2️⃣ Nesting
nav {
  background: $primary-color;
  ul {
    margin: 0;
    padding: 0;
    list-style: none;
    li {
      display: inline-block;
      a {
        color: white;
        text-decoration: none;
        &:hover {
          color: $secondary-color;
        }
      }
    }
  }
}

// 3️⃣ Mixin (Reusable block)
@mixin flex-center {
  display: flex;
  align-items: center;
  justify-content: center;
}

// 4️⃣ Use mixin
.hero {
  @include flex-center;
  height: 100vh;
  background: linear-gradient(to right, $primary-color, $secondary-color);
  color: white;
  font-family: $font-stack;
  font-size: 2rem;
}

// 5️⃣ Nesting with media query
@media (max-width: 600px) {
  .hero {
    font-size: 1.5rem;
  }
}

real-world developers organize large SCSS projects using partials, @use, and @import.

When your app grows, a single styles.scss file becomes hard to maintain.
Instead, we split SCSS into small “partial” files and import them into one main file.

Folder Structure Example

Here’s a standard SCSS project structure (used in React, Vite, or any web app):

/scss(folder)
 ├── _variables.scss     // variables for colors,fonts, etc.
 ├── _mixins.scss        // reusable mixins
 ├── _base.scss          // resets, base styles
 ├── _components.scss    // component-specific styles
 ├── _layout.scss        // header, footer, grid, etc.
 └── styles.scss         // main entry file (imports all above)

Files starting with _ (underscore) are partials — they won’t compile to CSS directly.

1️⃣ _variables.scss

// Define global variables
$primary-color: #007bff;
$secondary-color: #6c757d;
$font-family: 'Poppins', sans-serif;
$spacing-unit: 1rem;

2️⃣ _mixins.scss
// Define reusable mixins
@mixin flex-center {
  display: flex;
  align-items: center;
  justify-content: center;
}

@mixin responsive-font($size) {
  font-size: $size;
  @media (max-width: 600px) {
    font-size: $size * 0.8;
  }
}

3️⃣ _base.scss
// CSS reset and base styles
* {
  margin: 0;
  padding: 0;
  box-sizing: border-box;
}

body {
  font-family: $font-family;
  background: #f9f9f9;
  color: #333;
}

4️⃣ _layout.scss
header {
  background: $primary-color;
  padding: $spacing-unit;
  color: white;
}

footer {
  background: $secondary-color;
  padding: $spacing-unit;
  color: white;
  text-align: center;
}

5️⃣ _components.scss
.button {
  @include flex-center;
  padding: $spacing-unit;
  background-color: $primary-color;
  color: white;
  border: none;
  border-radius: 6px;
  cursor: pointer;
  transition: 0.3s;

  &:hover {
    background-color: darken($primary-color, 10%);
  }
}

.card {
  background: white;
  padding: $spacing-unit * 2;
  border-radius: 10px;
  box-shadow: 0 2px 5px rgba(0,0,0,0.1);

  h3 {
    @include responsive-font(1.5rem);
    margin-bottom: $spacing-unit;
  }
}

6️⃣ styles.scss (Main file)

This file imports or uses all the partials.

Option A: Old syntax — @import
@import 'variables';
@import 'mixins';
@import 'base';
@import 'layout';
@import 'components';

Option B: Modern syntax — @use ✅

Recommended for new projects.

@use 'variables';
@use 'mixins';
@use 'base';
@use 'layout';
@use 'components';


🧠 Tip: With @use, you must prefix variables/mixins unless you define them as global.

Example:

.hero {
  background: variables.$primary-color;
  @include mixins.flex-center;
}


Using in React/Vite

Install Sass:

npm install sass


Import the main SCSS file:

import './scss/styles.scss';


Done — React/Vite automatically compiles it.

| Best Practice                                               | Why It Matters                       |
| ----------------------------------------------------------- | ------------------------------------ |
| Use variables for colors and fonts                          | Consistent design                    |
| Create separate files for layout, components, and utilities | Easier to scale                      |
| Prefer `@use` instead of `@import`                          | Modern and avoids variable conflicts |
| Keep nesting shallow (max 3 levels)                         | Better performance                   |
| Leverage mixins and functions                               | Reduce repetitive code               |
